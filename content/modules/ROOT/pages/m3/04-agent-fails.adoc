= Confirm the Agent Is Locked Out
:numbered:
:icons: font
:source-highlighter: highlight.js

Nothing about the agent has changed. It is the same image you deployed at the end of Module 2, calling the same two MCP servers at the same two URLs. What changed is that both of those servers now ask for a token, and the agent has never had one to send.

== Run the handshake again

This is the same command from the first page of this module, unchanged:

[source,sh,role="copypaste",subs="attributes+"]
----
curl -i -X POST https://globex-store-mcp.{openshift_subdomain}/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}'
----

[source,text]
----
HTTP/1.1 401 Unauthorized
www-authenticate: Bearer
----

And the complaints server:

[source,sh,role="copypaste",subs="attributes+"]
----
curl -i -X POST https://globex-complaints.{openshift_subdomain}/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}'
----

Both routes are closed -- to `curl`, and to the agent, which the servers cannot tell apart from it.

== Watch the agent get the same answer

Open the https://console-openshift-console.{openshift_subdomain}/k8s/ns/globex-store-mcp/pods[pods in the `globex-store-mcp` project^], click the running pod and select the *Logs* tab. The 401s there are the agent's.
