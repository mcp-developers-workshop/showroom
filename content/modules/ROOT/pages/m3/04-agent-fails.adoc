== Confirm it from the command line

The same handshake from the first page of this module, unchanged:

[source,sh,role="copypaste",subs="attributes+"]
----
curl -i -X POST https://globex-store-mcp.{openshift_subdomain}/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}'
----

[source,text]
----
HTTP/1.1 401 Unauthorized
www-authenticate: Bearer
----

The route is closed. That is the fix from the last two pages working exactly as intended -- and it has taken the agent down with it, because the agent is just another anonymous caller.

== Why this had to happen to both servers

The agent has two MCP clients, `orders` and `complaint`. If only one server had been secured, the agent would have kept working for some prompts and failed for others, depending on which tool the model decided to reach for first. Securing both makes the failure unambiguous.

The fix is not to reopen the servers. It is to give the agent an identity.
