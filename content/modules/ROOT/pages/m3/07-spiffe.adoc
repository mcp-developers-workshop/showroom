== Why the client secret is not enough

`globex-mcp-client`'s secret is a long-lived bearer credential, and in the last section you committed one to a Git repository to make the agent work. That is the honest state of what you built:

* Anything holding that string *is* the agent, from anywhere, until someone changes it.
* Nothing attests that the caller is the workload it claims to be. Keycloak checks that the secret is correct, not that the process presenting it is the agent running in your cluster.
* Rotation is manual, which in practice means it does not happen.

SPIFFE replaces the shared secret with an identity the platform issues and attests, scoped to where the workload actually runs, and short-lived by construction. The agent stops holding a password and starts proving what it is.

== What Step 2 builds

A SPIRE agent attests the workload and issues it a short-lived JWT-SVID. Keycloak is configured to accept that SVID in place of the client secret, resolving to the same Keycloak client the agent already uses -- so the MCP servers need no change, and the two `quarkus.oidc-client.*` blocks from the last page stay. What goes away is the secret in `values.yaml`.
