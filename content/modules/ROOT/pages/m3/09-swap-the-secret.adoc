= SPIFFE Step 3: Swap the Secret for the SVID
:numbered:
:icons: font
:source-highlighter: highlight.js

[IMPORTANT]
====
This page works in the *`globex-complaint-agent-helm`* repository, in the GitLab web editor. Two files, `values.yaml` and `templates/secret.yaml`.
====

== Add the SPIFFE values

In `values.yaml`, add a second block next to the `spiffeHelper` one:

[source,yaml,role="copypaste"]
----
spiffe:
  trustDomain: globex.com
  namespace: globex-complaint-agent
  serviceAccount: globex-complaint-agent
  clientId: globex-agent-spiffe
  oidcIssuer: spiffe
  tokenPath: /svids/jwt.token
----

== Point both OIDC clients at the SVID

In `templates/secret.yaml`, replace the six `quarkus.oidc-client.*` lines you added in `Authenticate the Agent to the MCP Servers` with these. Only `auth-server-url` survives unchanged:

[source,yaml,role="copypaste"]
----
    quarkus.oidc-client.orders.auth-server-url={{ .Values.oidcClient.orders.authServerUrl }}
    quarkus.oidc-client.orders.client-id={{ .Values.spiffe.clientId }}
    quarkus.oidc-client.orders.credentials.jwt.token-path={{ .Values.spiffe.tokenPath }}
    quarkus.oidc-client.orders.credentials.jwt.source=bearer
    quarkus.oidc-client.orders.credentials.jwt.issuer={{ .Values.spiffe.oidcIssuer }}
    quarkus.oidc-client.orders.credentials.jwt.subject=spiffe://{{ .Values.spiffe.trustDomain }}/ns/{{ .Values.spiffe.namespace }}/sa/{{ .Values.spiffe.serviceAccount }}

    quarkus.oidc-client.complaint.auth-server-url={{ .Values.oidcClient.complaint.authServerUrl }}
    quarkus.oidc-client.complaint.client-id={{ .Values.spiffe.clientId }}
    quarkus.oidc-client.complaint.credentials.jwt.token-path={{ .Values.spiffe.tokenPath }}
    quarkus.oidc-client.complaint.credentials.jwt.source=bearer
    quarkus.oidc-client.complaint.credentials.jwt.issuer={{ .Values.spiffe.oidcIssuer }}
    quarkus.oidc-client.complaint.credentials.jwt.subject=spiffe://{{ .Values.spiffe.trustDomain }}/ns/{{ .Values.spiffe.namespace }}/sa/{{ .Values.spiffe.serviceAccount }}
----

[WARNING]
====
Add these *in place of* the old lines, not alongside them. `client-id` appeared on the earlier page too, and a properties file with the same key twice does not merge or error -- the last one silently wins. Two `client-id` lines means you cannot tell which client the agent is actually presenting.

No trailing spaces at the end of these lines either. This is the same YAML literal scalar as before, and a space after `}}` ends up inside the value.
====

`source=bearer` is what tells Quarkus the JWT is already signed and is to be sent as-is. Without it, Quarkus mints and signs its own assertion, which is the normal RFC 7523 flow but would discard the SVID. The subject is the SPIFFE ID the SVID carries, and it has to match the `jwt.credential.sub` recorded on the Keycloak client.

Both clients now send the same `client-id`. That is the shift this page makes: earlier the agent had two Keycloak identities, one per downstream server, each with its own secret. It now has one identity -- itself -- and proves it the same way to both.

== Delete the old credentials

Nothing reads `oidcClient.orders.clientId`, `oidcClient.complaint.clientId`, or either `secret` any more, so delete those four entries from `values.yaml` and leave the two `authServerUrl` entries. Leaving a live secret in Git after a page about removing it defeats the exercise.
