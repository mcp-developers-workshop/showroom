== Add the client assertion type filter

When Quarkus authenticates with a JWT instead of a secret, it sends `client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer`, which is what RFC 7523 specifies. Keycloak's SPIFFE support expects `urn:ietf:params:oauth:client-assertion-type:jwt-spiffe`, and no configuration setting bridges the two. One class rewrites the value in the request body on its way to Keycloak.

In a terminal in the `globex-complaint-agent` window:

[source,sh,role="copypaste"]
----
mkdir -p src/main/java/org/globex/retail/ai/complaint/spiffe
touch src/main/java/org/globex/retail/ai/complaint/spiffe/SpiffeClientAssertionTypeRequestFilter.java
----

[source,java,role="copypaste"]
----
package org.globex.retail.ai.complaint.spiffe;

import io.quarkus.arc.Unremovable;
import io.quarkus.oidc.common.OidcRequestFilter;
import io.smallrye.mutiny.Uni;
import io.vertx.mutiny.core.buffer.Buffer;
import jakarta.annotation.Priority;
import jakarta.enterprise.context.ApplicationScoped;

@ApplicationScoped
@Priority(500)
@Unremovable
public class SpiffeClientAssertionTypeRequestFilter implements OidcRequestFilter {

    private static final String DEFAULT_ASSERTION_TYPE =
        "urn%3Aietf%3Aparams%3Aoauth%3Aclient-assertion-type%3Ajwt-bearer";
    private static final String SPIFFE_ASSERTION_TYPE =
        "urn%3Aietf%3Aparams%3Aoauth%3Aclient-assertion-type%3Ajwt-spiffe";

    @Override
    public Uni<Void> filter(OidcRequestFilterContext context) {
        Buffer body = context.requestBody();
        if (body != null) {
            String bodyString = body.toString();
            if (bodyString.contains(DEFAULT_ASSERTION_TYPE)) {
                context.requestBody(Buffer.buffer(bodyString.replace(DEFAULT_ASSERTION_TYPE, SPIFFE_ASSERTION_TYPE)));
            }
        }
        return Uni.createFrom().voidItem();
    }
}
----

The values are URL-encoded because this rewrites a form-encoded body, not a header. `@Unremovable` keeps Quarkus from discarding a bean nothing injects.

An `OidcRequestFilter` applies to every outgoing OIDC request the application makes, so one class covers both OIDC clients. This is the only Java change in the SPIFFE steps -- the two auth providers from `Authenticate the Agent to the MCP Servers` are untouched, and no extension is added.
