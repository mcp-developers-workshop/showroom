= Require a Token on the Complaints MCP Server
:numbered:
:icons: font
:source-highlighter: highlight.js

The orders server is locked down; the complaints server is still open. Module 2 treated it as something already running on the cluster, so this is the first time you see its source.

Both have to be secured before the next page. Which tool the agent reaches for is the model's choice for a given prompt, so with only one server closed the failure may not show up at all.

== Clone the repository

Clone it the same way, into its own window:

[source,text,role="copypaste",subs="attributes+"]
----
https://gitlab-gitlab.{openshift_subdomain}/globex/globex-complaints.git

== What is in the repository

A Quarkus application backed by the Globex Postgres database, with *two* MCP servers in one deployment:

[source,text]
----
src/main/java/org/globex/retail/complaints/
├── mcp/ComplaintsMcp.java          <1>
├── mcp/ComplaintsReadMcp.java      <2>
├── rest/ComplaintResource.java
├── service/ComplaintService.java
├── service/DatabaseService.java
└── persistence/Complaint.java
src/main/resources/application.properties
----

<1> The tools you used in Module 2 -- `create_complaint`, `get_complaint`, `update_complaint` -- served at `/mcp`.
<2> A second, read-only server at `/read/mcp`. Module 5 uses it.

`application.properties` already declares both:

[source,properties]
----
quarkus.mcp.server.http.root-path=/mcp
quarkus.mcp.server.read.http.root-path=/read/mcp
----

Named MCP servers are how one Quarkus application serves more than one endpoint. `quarkus.mcp.server.read.*` configures the server named `read`; the unnamed block configures the default.

== Add the OIDC extension

No Maven wrapper in this repository, so plain `mvn`:

[source,sh,role="copypaste"]
----
mvn quarkus:add-extension -Dextensions="oidc"
----

== Secure both endpoints

Add to `src/main/resources/application.properties`:

[source,properties,role="copypaste",subs="attributes+"]
----
# OIDC - validate access tokens from the internal realm
quarkus.oidc.auth-server-url=https://sso.{openshift_subdomain}/realms/internal
quarkus.oidc.client-id=globex-complaints-server

# Secure both MCP endpoints
quarkus.http.auth.permission.mcp.paths=/mcp,/mcp/*,/read/mcp,/read/mcp/*
quarkus.http.auth.permission.mcp.policy=authenticated
quarkus.http.cors.enabled=true
----

Both paths are listed. The read-only server reads the same complaints table. `globex-complaints-server` is already in the `internal` realm, like the orders client on the previous page.
