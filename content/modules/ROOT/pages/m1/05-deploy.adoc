== Commit Your MCP Server

=== Stage and commit

Open a new terminal in IBM Bob (*Terminal* -> *New Terminal*) -- dev mode and the MCP Inspector are still running in the other two. From inside the `globex-store-mcp` folder:

[source,sh,role="copypaste"]
----
git add .
git commit -m "my first MCP server"
----

=== Push to GitLab

[source,sh,role="copypaste"]
----
git push
----

The push is the first command that talks to GitLab, so this is where you are prompted for credentials. Bob asks for them in an input box at the top of the window, username first and then password, each confirmed with kbd:[Enter]:

image::m1/bob-git-credentials.png[link=self,window=_blank]

Use the workshop developer account:

[cols="1,2", options="header"]
|===
| Field | Value

| Username
| `developer`

| Password
| `{common_password}`
|===

Refresh the project in GitLab to see the pushed code.

== Watch the Deployment in ArgoCD

ArgoCD (Red Hat OpenShift GitOps) manages both the build and the deployment of the MCP server. Your push triggers a build, and the deployment rolls out the image the build produces.

=== Log in

Open https://openshift-gitops-server-openshift-gitops.{openshift_subdomain}/[the ArgoCD console^].

Sign in with the workshop GitOps account:

[cols="1,2", options="header"]
|===
| Field | Value

| Username
| `{openshift_gitops_user}`

| Password
| `{openshift_gitops_password}`
|===

[NOTE]
====
Accept the certificate warning if your browser shows one. If the page shows a *Log in via OpenShift* button instead of a login form, use the plain login option below it.
====

=== Find the application

You land on the *Applications* dashboard, which lists every application the workshop environment manages:

image::m1/argocd-applications.png[link=self,window=_blank]

Click the `globex-store-mcp` tile. The application details tree opens:

image::m1/argocd-globex-store-mcp.png[link=self,window=_blank]

The tree shows the resources that make up the application. When the build pushes the new image, a new replica set and pod appear with an age of a few seconds while the older ones are scaled down.

*App Health* reads *Progressing* while the new pod starts, then switches to *Healthy* once the new image is serving. This might take a minute or two, depending on how long the build took.
