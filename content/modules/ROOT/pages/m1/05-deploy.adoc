== Commit Your MCP Server

Open a new terminal in IBM Bob (*Terminal* -> *New Terminal*). From inside the `globex-store-mcp` folder, run the following commands to stage and commit your changes:

[source,sh,role="copypaste"]
----
git add .
git commit -m "my first MCP server"
----

=== Push to GitLab

[source,sh,role="copypaste"]
----
git push
----

The push is the first command that connects to GitLab, so Bob prompts you for credentials. Enter your username in the input box at the top of the window and press kbd:[Enter]. Enter your password and press kbd:[Enter] again.

image::m1/bob-git-credentials.png[link=self,window=_blank]

Use the workshop developer account:

[cols="1,2", options="header"]
|===
| Field | Value

| Username
| `developer`

| Password
| `{common_password}`
|===


== Watch the Deployment in OpenShift Pipelines

The GitLab push triggers an OpenShift Pipelines build, which creates a new container image. Argo CD (Red Hat OpenShift GitOps) then detects the updated image and deploys it to OpenShift.

You can access the Pipeline Runs via the OpenShift console at https://console-openshift-pipelines.apps.{openshift_subdomain}/[the OpenShift console^]. Sign in with your IBM ID if prompted.

=== Find the application

You land on the *Applications* dashboard, which lists every application the workshop environment manages:

image::m1/argocd-applications.png[link=self,window=_blank]

Click the `globex-store-mcp` tile. The application details tree opens:

image::m1/argocd-globex-store-mcp.png[link=self,window=_blank]

The tree shows the resources that make up the application. When the build pushes the new image, a new replica set and pod appear with an age of a few seconds while the older ones are scaled down.

*App Health* reads *Progressing* while the new pod starts, then switches to *Healthy* once the new image is serving. This might take a minute or two, depending on how long the build took.
