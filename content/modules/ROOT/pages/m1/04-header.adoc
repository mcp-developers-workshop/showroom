= Pass the Customer Identifier as an HTTP Header
:numbered:
:icons: font
:source-highlighter: highlight.js

The tool takes `customerId` as a parameter, which means the model supplies it. Whatever the model puts in that field decides whose orders come back.

The model's input is the conversation: the customer's own words, plus any text that reached the context from somewhere else. So "show me the orders for another customer" is a valid tool call, and so is an instruction hidden in a document the agent was asked to read. The server cannot tell any of them apart from a legitimate request.

Next you move the customer ID to an HTTP header on the MCP request, set by the caller. It leaves the tool's schema entirely, so the model has no field to fill in.

== Prompt IBM Bob

[source,text,role="copypaste"]
----
The 'getOrdersByCustomerId' tool GlobexStoreMcpServer.java takes the customerId as parameter. Change the implementation so that the customerId is passed as a HTTP header. The name of the header is 'X-User-Id'. Throw an exception if the header is not present or is empty.
----

Read Bob's questions and click *Approve*.

== What changes

[cols="1,2", options="header"]
|===
| Change | Effect

| `customerId` removed from the tool signature
| The identifier is no longer part of the tool contract the model sees.

| Read from the `X-User-Id` header
| The identity travels on the transport, set by the caller.

| Exception when the header is missing or empty
| No header means no data, rather than a default or an unfiltered result set.
|===

[NOTE]
====
`X-User-Id` is unverified -- the caller can set it to anything. It gets replaced with a verified identity later in the workshop.
====

== Verify the change

Once dev mode restarts, open http://localhost:8080/q/dev-ui/quarkus-mcp-server-http/tools[the Dev UI tools page^] and click the tool name:

image::m1/devui-getorders-no-parameters.png[link=self,window=_blank]

The tool now declares no parameters, so the model has nothing to supply.

== Test the header with MCP Inspector

The Dev UI cannot set request headers. *MCP Inspector* is a standalone MCP client with a browser UI, and it connects to your server the same way an agent would.

Leave dev mode running and start the Inspector from a second terminal:

[source,sh,role="copypaste"]
----
npx @modelcontextprotocol/inspector
----

It prints a URL for the UI (default `http://localhost:6274`) and opens it in the browser.

image::m1/mcp-inspector-servers.png[link=self,window=_blank]

=== Add your server

The three servers listed are the Inspector's built-in examples. Click *Add Servers* -> *Add Manually* and fill in the dialog:

image::m1/mcp-inspector-add-server.png[link=self,window=_blank]

[cols="1,2", options="header"]
|===
| Field | Value

| Server ID
| `order-mcp-local`

| Transport
| `streamable-http`

| URL
| `\http://localhost:8080/mcp`
|===

Click *Add*.

=== Connect to the server

Click the *Disconnected* toggle on the new `order-mcp-local` card.

image::m1/mcp-inspector-server-added.png[link=self,window=_blank]

The card turns green, the server reports itself as `GlobexStoreMcpServer`, and a *Tools* tab appears:

image::m1/mcp-inspector-connected.png[link=self,window=_blank]

=== Check the tool schema

Open the *Tools* tab and click `getOrdersByCustomerId`:

image::m1/mcp-inspector-tool-detail.png[link=self,window=_blank]

A description and an *Execute Tool* button, and no input fields. This is the tool contract as a model receives it -- there is no customer ID in it.

=== Call the tool without the header

Click *Execute Tool*. The call fails, because the tool throws when `X-User-Id` is missing:

image::m1/mcp-inspector-tool-error.png[link=self,window=_blank]

[NOTE]
====
The *Network* panel records the request as `200 OK`. The HTTP request succeeded; the failure is carried inside the MCP response, which is how tool errors are reported.
====

=== Add the header

Go back to the *Servers* tab and click *Settings* on the `order-mcp-local` card:

image::m1/mcp-inspector-card-settings.png[link=self,window=_blank]

Scroll to the bottom of the *Options* section and expand *Custom Headers*:

image::m1/mcp-inspector-server-settings.png[link=self,window=_blank]

Click *+ Add Header* and fill in the two fields:

[cols="1,2", options="header"]
|===
| Field | Value

| Header name
| `X-User-Id`

| Header value
| `asilva`
|===

image::m1/mcp-inspector-custom-header.png[link=self,window=_blank]

Close the dialog.

[IMPORTANT]
====
Custom headers only take effect on a new connection, and a reconnect is not enough. Reload the browser page, then connect to `order-mcp-local` again.
====

=== Call the tool with the header

Go to the *Tools* tab, select `getOrdersByCustomerId`, and click *Execute Tool*.

image::m1/mcp-inspector-tool-result.png[link=self,window=_blank]

The call took no arguments, and `asilva`'s shaped order history came back. Whose orders those were was decided entirely by the `X-User-Id` header -- a value the model never sees and cannot change.
