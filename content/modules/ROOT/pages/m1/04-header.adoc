= Keep Identities Out of the Model Context
:numbered:
:icons: font
:source-highlighter: highlight.js


The tool currently takes `customerId` as a parameter, which means the model supplies it. The model can therefore decide whose data to retrieve, or be steered by a user into retrieving someone else's data.

Instead, pass the customer ID as an HTTP header set by the caller. The identifier is no longer part of the tool schema, so the model has nothing to provide or change.

== Prompt IBM Bob

[source,text,role="copypaste"]
----
The 'getOrdersByCustomerId' tool GlobexStoreMcpServer.java takes the customerId as parameter. Change the implementation so that the customerId is passed as a HTTP header. The name of the header is 'X-User-Id'. Throw an exception if the header is not present or is empty.
----

Read Bob's questions and click *Approve*.

== Verify the change

Once dev mode restarts, open http://localhost:8080/q/dev-ui/quarkus-mcp-server-http/tools[the Dev UI tools page^] and click the tool name:

image::m1/devui-getorders-no-parameters.png[link=self,window=_blank]

The tool now has no parameters. The customer ID is no longer part of the tool contract.


== Test the header with MCP Inspector

The Dev UI cannot set request headers, so use *MCP Inspector* to test the server with a custom header.

Leave dev mode running and start the Inspector from a second terminal:

[source,sh,role="copypaste"]
----
npx @modelcontextprotocol/inspector
----

The Inspector opens in your browser.

image::m1/mcp-inspector-servers.png[link=self,window=_blank]

=== Add your MCP server

Click *Add Servers* -> *Add Manually* and enter:

image::m1/mcp-inspector-add-server.png[link=self,window=_blank, width=70%]

[cols="1,2", options="header"]
|===
| Field | Value

| Server ID
| `order-mcp-local`

| Transport
| `streamable-http`

| URL
| `\http://localhost:8080/mcp`
|===

Click *Add*.

=== Connect to the server

Click the *Disconnected* toggle on the new `order-mcp-local` card.

image::m1/mcp-inspector-server-added.png[link=self,window=_blank]

The card turns green, and a *Tools* tab appears:

image::m1/mcp-inspector-connected.png[link=self,window=_blank]

=== Check the tool schema

Open the *Tools* tab and select `getOrdersByCustomerId`:

image::m1/mcp-inspector-tool-detail.png[link=self,window=_blank]

There are no input fields. The customer ID is not part of the tool schema exposed to the model.

=== Call the tool without the header

Click *Execute Tool*. 

The call fails, because the tool throws when `X-User-Id` is missing:

image::m1/mcp-inspector-tool-error.png[link=self,window=_blank]

=== Add the header

Go back to the *Servers* tab and click *Settings* for `order-mcp-local`.

image::m1/mcp-inspector-card-settings.png[link=self,window=_blank]

Under the *Options*, expand *Custom Headers*, and click *+ Add Header*.

[cols="1,2", options="header"]
|===
| Field | Value

| Header name
| `X-User-Id`

| Header value
| `asilva`
|===

image::m1/mcp-inspector-custom-header.png[link=self,window=_blank]

Close the dialog.

[IMPORTANT]
====
Reload the browser page before reconnecting to the server. Custom headers are applied when the connection is established.
====

=== Call the tool with the header

Reconnect to `order-mcp-local`, then go to the *Tools* tab and execute `getOrdersByCustomerId`.

image::m1/mcp-inspector-tool-result.png[link=self,window=_blank]

The tool was called with no arguments, but asilva's order history was returned.

The customer ID came from the `X-User-Id` header, not from the model.

The header is still unverified. Module 3 closes that gap by authenticating the caller and using a verified identity.
