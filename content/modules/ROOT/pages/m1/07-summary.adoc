= Summary
:numbered:
:icons: font
:source-highlighter: highlight.js


You built a brownfield MCP server over an existing REST API and deployed it to OpenShift:

* Generated a Quarkus MCP server from the Globex Store OpenAPI specification with IBM Bob, exposing one tool over streamable HTTP.
* Minimized the tool response to the data the agent needs: no shipping address, no prices, and product names resolved from a second endpoint.
* Moved the customer identifier out of the tool signature and into the `X-User-Id` HTTP header, so the caller provides it rather than the model.
* Verified the changes with MCP Inspector in dev mode.
* Pushed the code to GitLab, watched the pipeline build the image and the deployment roll it out, then tested the deployed server.

The implementation followed three basic decisions:

* *Wrap existing APIs* without changing the underlying service.
* *Keep tools narrow* and return only the data the agent needs.
* *Keep identity out of the model contract.*

There is still one important gap: `X-User-Id` is not verified. Anyone who can reach the server can set it to another customer's ID.

Module 3 closes that gap by authenticating the caller and using a verified identity.
