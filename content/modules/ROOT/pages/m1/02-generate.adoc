== Generate the MCP Server with IBM Bob

The Globex Store exposes a REST API described by an OpenAPI specification. Rather than writing the MCP server by hand, use IBM Bob to generate a Quarkus MCP server that wraps the existing API and exposes a single tool.

This is the brownfield pattern: the existing API remains unchanged, while the MCP server sits in front of it and exposes selected capabilities to the AI application.

=== Prompt IBM Bob

With `globex-store-mcp` open in Bob, enter the following prompt:

[source,text,role="copypaste",subs="attributes"]
----
Within the globex-store-mcp folder, Download the openapi spec document located at https://globex-store.{openshift_subdomain}/q/openapi . Create a mcp server called "GlobexStoreMcpServer" which exposes a tool called "getOrdersByCustomerId" to get the orders for a given customerId. The tool implementation should connect to the API described in the openAPI spec document and return the API response. The mcp server should use the streamable http transport. Use the appropriate quarkus extension for the mcp server. Use 'asilva' as the customer id when testing.
----

=== Approve Bob's tasks

Bob breaks the request into tasks and asks for confirmation before running them. You can expect several prompts. 

Read each prompt, click *Approve*, and continue until Bob reports that the work is complete.

=== Review Bob's summary

Bob builds and tests the project, then provides a summary of what it created.

Review the summary to understand what Bob changed before moving on.

=== Review the generated configuration

Open `src/main/resources/application.properties`. Bob should have configured the MCP server's identity and the base URL of the Globex Store API:

[source,properties,subs="attributes+"]
----
# MCP Server identity
quarkus.mcp.server.server-info.name=GlobexStoreMcpServer
quarkus.mcp.server.server-info.version=1.0.0-SNAPSHOT

# Globex Store REST client base URL
quarkus.rest-client.globex-store-api.url=https://globex-store.{openshift_subdomain}
----

The URL came from the `servers` block of the OpenAPI document Bob downloaded.

== Verify the Tool in the Quarkus Dev UI

The Quarkus MCP server extension adds a Dev UI page where you can view and invoke the tools registered by your MCP server.

=== Start the application in dev mode

Start the new MCP server from a terminal in the `globex-store-mcp` folder:

[source,sh,role="copypaste"]
----
./mvnw quarkus:dev
----

Wait for the startup message:

....
Listening on: http://localhost:8080
....

=== Confirm the tool is registered

Open http://localhost:8080/q/dev-ui/quarkus-mcp-server-http/tools[the Dev UI tools page^]. One tool is listed:

[cols="1,2", options="header"]
|===
| Tool | Description

| `getOrdersByCustomerId`
| Get all orders for a given customer ID from the Globex Store
|===

If nothing is listed, check the dev mode terminal for a failed restart.

[NOTE]
====
Bob may have chosen a different name for the tool such as `getOrders`. Use whatever name your Dev UI shows wherever these instructions say `getOrdersByCustomerId`.
====

=== Call the tool

Click the tool name to open the Tool call input dialog.

Enter the following customer ID and click *Call*:

image::m1/devui-tool-call-input.png[link=self,window=_blank]

[cols="1,2", options="header"]
|===
| Field | Value

| `customerId`
| `asilva`
|===

Leave *Force new session* unticked and *Bearer Token* empty. 

At this point, the server has no authentication. Anyone who can reach the server can invoke the tool and request any customer's orders. Module 3 addresses this by adding authentication and verifying the identity associated with the request.

image::m1/devui-tool-call-result-full.png[link=self,window=_blank]

Notice that the complete API response is returned, including information that the AI application may not actually need. Later in this module, you will minimise the tool response to expose only the data required by the agent.
