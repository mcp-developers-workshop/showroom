= Minimize the Data Returned by the Tool
:numbered:
:icons: font
:source-highlighter: highlight.js

The tool currently returns the API response unchanged, including `asilva`'s home address and the prices of the products they ordered.

Everything returned by a tool becomes part of the model context. If the agent only needs to answer "what did I order?", it does not need the address or prices.

[NOTE]
====
Minimize data at the tool. Once data reaches the model, you cannot reliably take it back.
====

== Prompt IBM Bob

[source,text,role="copypaste",subs="attributes"]
----
Change the contents of the JSON data returned by the mcp server. The orders in the history should not contain the shipping address. The product line items should not contain the price, but they should contain the product code, quantity and the product name. This might need additional calls to the backend api described in https://globex-store.{openshift_subdomain}/q/openapi . Use 'asilva' as the customer id when testing.
----

As before, read Bob's questions and click *Approve*.

[NOTE]
====
The customer ID gives Bob real data to test with. Otherwise, Bob tests against invented ones, gets empty responses back, and cannot tell a working change from a broken one.
====

== Verify the new minimised response 

After Bob rebuilds the application, call the tool again from the http://localhost:8080/q/dev-ui/quarkus-mcp-server-http/tools[Dev UI tools page^] using `asilva`:

image::m1/devui-tool-call-result-shaped.png[link=self,window=_blank]

The response now contains only the data the agent needs: order details, product codes, product names, and quantities. No shipping address and no prices.

The address and the prices are still in the Globex Store API, available to the web application and no longer available on a tool call.
