= Shape the Data Returned by the Tool
:numbered:
:icons: font
:source-highlighter: highlight.js

The tool returns the API response untouched, and that response contains `asilva`'s home address.

Everything a tool returns is sent to the model. In most deployments, that means customer data leaves your network and is sent to a hosted model provider. It becomes part of the prompt, and may then appear in model logs, traces, transcripts, and later responses.

The address and prices make sense for the Globex web application, which needs them to render the page. An agent answering "what did I order?" needs neither.

[NOTE]
====
This is data minimisation, and the tool is where you enforce it. Once data is in the prompt, you cannot reliably take it back.
====

== Prompt IBM Bob

[source,text,role="copypaste",subs="attributes"]
----
Change the contents of the JSON data returned by the mcp server. The orders in the history should not contain the shipping address. The product line items should not contain the price, but they should contain the product code, quantity and the product name. This might need additional calls to the backend api described in https://globex-store.{openshift_subdomain}/q/openapi . Use 'asilva' as the customer id when testing.
----

As before, read Bob's questions and click *Approve*.

[NOTE]
====
The last sentence saves time. Without a customer ID that exists, Bob tests against invented ones, gets empty responses back, and cannot tell a working change from a broken one.
====

== What changes

[cols="1,2", options="header"]
|===
| Dropped | Why

| Shipping address
| Personal data. Identifies where a named customer lives.

| Line item price
| Commercially sensitive, and irrelevant to the question being asked.
|===

Each line item keeps its product code and quantity, and gains a product name.

[NOTE]
====
The orders endpoint returns product codes, not names, so Bob has to call a second endpoint from the same OpenAPI specification to resolve them. That is what the sentence about additional calls allows for.

`/services/catalog/product/list/{ids}` takes a list, so one call resolves every code -- not one call per line item.
====

== Verify the new minimised response 

Bob rebuilds and re-tests. Once dev mode has restarted, call the tool again from http://localhost:8080/q/dev-ui/quarkus-mcp-server-http/tools[the Dev UI tools page^] with the same `asilva` customer ID:

image::m1/devui-tool-call-result-shaped.png[link=self,window=_blank]

Each order is now `id`, `customer`, `timestamp`, and a `lineItems` array of `productCode`, `productName` and `quantity` -- and nothing else. Same question, same customer, none of the personal or commercial data.

The address and the prices are still in the Globex Store API, available to anything with a legitimate reason to read them. They no longer leave the network on a tool call.
