= Read One Turn End to End
:numbered:
:icons: font
:source-highlighter: highlight.js

Open the newest trace in Langfuse and look at four things.

== The span tree

The whole turn, nested by caller, with a duration on every node. Check that all three `service.name` values are there -- `globex-complaint-agent`, and whichever MCP servers the model used.

This answers the questions the logs could not: which service was called, in what order, and where the time went. The model call is usually most of it.

== A generation

Open a span named for a model call. Langfuse shows it as a generation, with:

* *Input* -- the prompt as actually sent, including the system message and the tool definitions that `quarkus-langchain4j-mcp` generated from each server's `tools/list`. This is assembled at runtime and does not exist in the source anywhere.
* *Output* -- what the model returned.
* *Usage* -- input and output token counts.

If there is more than one generation, the second one's Input contains the first tool's result in full.

== A tool call

Open a tool span. It carries the tool name, the arguments the model chose, and the result that came back.

== What the MCP server did

Expand the tool span. Underneath it is the MCP server's own span, and under that the work it did -- an outbound HTTP call to the Globex Store API, or JDBC spans carrying the SQL.

[NOTE]
====
If Input and Output are empty on the generation, the agent is missing one of the two extensions. `quarkus-langfuse` only switches on prompt and completion capture when it finds `quarkus-opentelemetry` alongside it.

If cost reads zero while tokens look right, that is a missing entry in Langfuse's model price table, not missing telemetry.
====
