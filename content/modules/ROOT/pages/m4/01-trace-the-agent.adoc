= Trace the Agent
:numbered:
:icons: font
:source-highlighter: highlight.js

[IMPORTANT]
====
This page works in the *`globex-complaint-agent`* window. Two extensions and eight properties, in one commit.
====

== Add the extensions

The agent has no Maven wrapper, so plain `mvn`:

[source,sh,role="copypaste"]
----
mvn quarkus:add-extension -Dextensions="opentelemetry,io.quarkiverse.langfuse:quarkus-langfuse"
----

`quarkus-opentelemetry` provides the SDK and the automatic instrumentation. `quarkus-langfuse` configures the OTLP exporter to point at Langfuse and turns on the LangChain4j span content, so you do not configure an endpoint, a protocol or an authentication header yourself.

That is the only code change. `quarkus-langchain4j` contributes a span per model call and `quarkus-langchain4j-mcp` a span per MCP tool call. Both have been on the classpath since Module 2 and neither emits anything until an OpenTelemetry SDK is present to receive it.

== Configure it

Add to `src/main/resources/application.properties`:

[source,properties,role="copypaste",subs="attributes+"]
----
# Langfuse
quarkus.langfuse.base-url={langfuse_internal_url}
quarkus.langfuse.public-key={langfuse_public_key}
quarkus.langfuse.secret-key={langfuse_secret_key}
quarkus.langfuse.devservices.enabled=false

# Put the prompt, completion, tool arguments and tool result on the spans
quarkus.langchain4j.tracing.include-prompt=true
quarkus.langchain4j.tracing.include-completion=true
quarkus.langchain4j.tracing.include-tool-arguments=true
quarkus.langchain4j.tracing.include-tool-result=true
----

`base-url` is the in-cluster service address, not the route you open in a browser. The agent and Langfuse are in the same cluster, so the traffic never leaves it and needs no TLS.

The extension builds the ingestion URL from `base-url` -- the default `trace-ingestion-url` is `${quarkus.langfuse.base-url}/${quarkus.langfuse.otel.trace-ingestion-path}`, and the path defaults to `api/public/otel/v1/traces`.

The four `quarkus.langchain4j.tracing.include-*` properties all default to `false`. Without them the spans carry the timings and the token counts but no content, and Langfuse shows Input and Output as `undefined`.

You do not set `quarkus.langfuse.otel.span-filter` here. It defaults to `ai-only`, which exports AI spans and their ancestors -- exactly what the agent produces. That is also what keeps the MCP clients' once-a-minute health pings out of the trace list, since they contain no AI span.

[WARNING]
====
This puts the Langfuse secret key in a Git repository and bakes it into the image -- the same trade the OpenAI key made in Module 2. Acceptable on a cluster that is destroyed at the end of the day, not otherwise.
====

The four `quarkus.langchain4j.tracing.include-*` properties, which control whether the prompt, completion, tool arguments and tool result appear on the spans, all default to `false`. You do not need to set them: `quarkus-langfuse` turns all four on when it sees `quarkus-opentelemetry` and `quarkus-langchain4j` together.

== Compile and push

[source,sh,role="copypaste"]
----
mvn clean compile
----

[source,sh,role="copypaste"]
----
git add .
git commit -m "send traces to Langfuse"
git push
----

The webhook starts the pipeline, which builds the image and then deletes the agent pod so the replacement picks it up. Both the extension and its configuration are in this one commit, so there is nothing to race and nothing to restart by hand.

The *Log View* tab shows the raw span, including `resourceAttributes`. That is where to confirm the spans are the agent's: `service.name` reads `globex-complaint-agent`, and `webengine.name` reads `Quarkus`. Nothing sets `service.name` -- `quarkus.otel.service-name` defaults to `quarkus.application.name`, which defaults to the Maven artifact ID.

Open the `completion gpt-4o-mini` span. *Input* is the prompt as actually sent -- the system message, the conversation so far, and the tool definitions generated from each MCP server's `tools/list`. None of that exists in one place in the source.

image::m4/langfuse-generation.png[link=self,window=_blank]

The metadata carries the `gen_ai.*` attributes the model call produced, including `gen_ai.response.finish_reasons`. A value of `TOOL_EXECUTION` means the model asked for a tool rather than answering, which is why *Output* is empty on that span -- the reply comes from the second model call, after the tool returns.

The tool span has no children yet. The agent records that it called a tool and how long it took; the next page adds the other side.

=== If no trace appears
