== Workshop Overview

Welcome to the *MCP in Practice for Developers* hands-on workshop.

This workshop is engineered to guide software architects, platform engineers, and developers from initial local prototyping ("laptops") to deploying secure, observable, and enterprise-ready Model Context Protocol (MCP) servers and AI agents in production ("production").

As enterprises move from Generative AI experimentation to agentic workflows, AI applications increasingly need to interact with enterprise systems and take action on behalf of users. Giving agents direct access to backend APIs and services, however, introduces significant security, data exposure, governance, and operational challenges.

The *Model Context Protocol (MCP)* provides a standardized way to expose capabilities to AI applications. In an enterprise architecture, MCP can become more than an integration mechanism: it can provide a controlled boundary between AI applications and enterprise capabilities.

This workshop demonstrates how to build that boundary using MCP, applying principles such as intent-based tool exposure, data minimization, zero-trust identity, end-to-end observability, and centralized governance on modern enterprise platforms such as Red Hat OpenShift.

== The Enterprise Challenge

AI agents are moving beyond generating text and are increasingly being used to *take action*: retrieving customer data, creating orders, updating records, invoking business services, and orchestrating workflows across enterprise systems.

This creates a new architectural challenge. An agent needs access to the *right capabilities and data*, but giving it direct access to enterprise APIs, databases, and services creates challenges around security, data exposure, governance, and operational visibility.

As agents and tools multiply, enterprises need to answer:

* *What should an agent be allowed to do?* +
How do we expose business capabilities without giving an agent unrestricted access to underlying APIs and systems?

* *What data should an agent see?* +
How do we prevent unnecessary, sensitive, or irrelevant backend data from entering the LLM context?

* *Who is the agent?* +
How do we establish workload identity and enforce authorization when an autonomous agent, rather than a human user, is making a request?

* *How do we know what happened?* +
How do we trace an agent's actions across LLM calls, MCP tools, APIs, and backend services when something goes wrong?

* *How do we govern hundreds or thousands of tools?* +
How do we prevent every agent from maintaining its own credentials, tool definitions, policies, and integrations?

The enterprise challenge is therefore not simply connecting an LLM to enterprise systems. It is creating a controlled, secure, and observable way for agents to interact with enterprise capabilities.

== The Solution: Model Context Protocol (MCP)
This workshop addresses these challenges by establishing an *Intentional Agent Architecture*:

1. *Exposing Intent over Resources:* Standardize agent capabilities into well-defined MCP tools rather than granting raw API access.
2. *Data Minimization & Sanitization:* Filter and massage backend payloads before they enter the LLM context window.
3. *Zero-Trust Security & Identity:* Authenticate agents using cryptographic SPIFFE/SPIRE workload identities and Keycloak OIDC service accounts.
4. *Observability:* Trace a single agent turn across the agent, both MCP servers and the model with OpenTelemetry, and read it in Langfuse.
5. *Centralized Governance:* Control tool sprawl with an enterprise MCP Gateway, keeping credentials and tool filtering rules in one place rather than copied into every agent.

== Environment & Architecture Overview

During this workshop, you will work within a dedicated Red Hat OpenShift Sandbox environment equipped with:

* *OpenShift Cluster Namespace:* Pre-provisioned workspace for building, running, and deploying microservices.
* *Quarkus Runtime & AI Assistance:* Modern Java framework with Quarkus MCP extensions and AI-assisted developer tooling.
* *Keycloak IAM & SPIRE Provider:* Identity management pre-configured for OIDC service accounts and native SPIFFE workload attestation.
* *Observability:* A Langfuse instance receiving OpenTelemetry traces over OTLP from the agent and both MCP servers.
* *MCP Gateway:* Centralized proxy and policy engine for managing agent-to-server connections, virtual servers and tool filtering.
