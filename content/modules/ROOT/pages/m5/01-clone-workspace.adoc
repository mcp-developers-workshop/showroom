= Clone the Workspace

:numbered:
:icons: font
:source-highlighter: highlight.js

You put the Globex complaints MCP server behind a watsonx Orchestrate agent with three artefacts: a *connection* that authenticates to Keycloak, an *MCP toolkit* that registers the remote server, and a *native agent* that uses its tools.

Each is a YAML file imported with the `orchestrate` CLI, and the order matters. The toolkit's `app_id` refers to the connection, so the connection must exist and hold valid credentials first. The agent's `tools` refer to the toolkit's tools, so the toolkit must be imported before the agent.

[NOTE]
====
The commands in this module use the watsonx Orchestrate ADK CLI (`orchestrate`). It must be installed and pointed at an active environment before you start.
====

== Open the workspace

Open the `globex-complaints-orchestrate` folder in Bob -- see xref:dev-setup-intro.adoc#open-a-repository[Open a Repository in IBM Bob].

[source,text]
----
├── connections/
│   └── globex-complaints-connection.yaml
├── toolkits/
│   └── globex-complaints.yaml
├── agents/
│   └── complaints_analyser.yaml
└── workspace_config.yaml
----

One folder per artefact kind, which is how the `orchestrate` CLI expects a workspace to be laid out.

== Set your cluster subdomain

The connection and the toolkit point at services on your cluster, and both ship with `<OPENSHIFT_SUBDOMAIN>` where the address goes. From a terminal in the `globex-complaints-orchestrate` folder:

[source,sh,role="copypaste",subs="attributes+"]
----
sed -i 's|<OPENSHIFT_SUBDOMAIN>|{openshift_subdomain}|g' \
  connections/globex-complaints-connection.yaml \
  toolkits/globex-complaints.yaml
----

`connections/globex-complaints-connection.yaml` now ends:

[source,yaml,subs="attributes+"]
----
    server_url: https://sso.{openshift_subdomain}/realms/internal
    token_url: https://sso.{openshift_subdomain}/realms/internal/protocol/openid-connect/token
----

and the `url` in `toolkits/globex-complaints.yaml` reads:

[source,yaml,subs="attributes+"]
----
url: https://globex-complaints.{openshift_subdomain}/read/mcp
----

Check nothing is left:

[source,sh,role="copypaste"]
----
grep -rn '<OPENSHIFT_SUBDOMAIN>' connections toolkits
----

No output means you are done. Both imports later in this module succeed against an address that does not resolve, so a missed replacement first shows up as a toolkit with no tools.
