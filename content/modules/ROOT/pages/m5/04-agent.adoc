= Define and Deploy the Agent
:numbered:
:icons: font
:source-highlighter: highlight.js

The agent is the one artefact worth writing as YAML. `orchestrate agents create` takes the model, style and tools as flags, but has nothing for the starter prompts or the welcome message.

== Step 1: Write the agent specification

[source,sh,role="copypaste"]
----
cat > complaints_analyser.yaml <<'EOF'
spec_version: v1
kind: native
name: complaints_analyser
display_name: Complaints Analyser
description: An agent that retrieves and analyses customer complaints, providing detailed summaries and actionable insights for product improvement.
llm: groq/openai/gpt-oss-120b
style: react_core
tools:
  - globex-complaints:database_info
  - globex-complaints:list_tables
  - globex-complaints:describe_tables
  - globex-complaints:read_query
starter_prompts:
  is_default_prompts: false
  prompts:
    - id: prompt_1
      title: Top complaint types
      subtitle: ''
      prompt: "What are the top 5 most common complaint types and how many times does each appear?"
      state: active
    - id: prompt_2
      title: Complaints by severity
      subtitle: ''
      prompt: "Show me a breakdown of complaints by severity. How many are Critical or High?"
      state: active
    - id: prompt_3
      title: Products by complaint volume
      subtitle: ''
      prompt: "Which products have the most complaints? Rank them by complaint volume."
      state: active
    - id: prompt_4
      title: Unresolved complaint themes
      subtitle: ''
      prompt: "What are the most frequent themes in unresolved complaints? What should we fix first?"
      state: active
    - id: prompt_5
      title: Product improvement report
      subtitle: ''
      prompt: "Give me a product improvement report based on the last 1000 complaints."
      state: active
welcome_content:
  welcome_message: Welcome to Complaints Analyser
  description: Retrieve and analyse customer complaints for actionable product improvement insights.
  is_default_message: false
instructions: |
  You are the Complaints Analyser, an AI assistant specialising in customer complaint analysis for product improvement.

  You have access to a complaints database through the globex-complaints toolkit.

  - Run database_info first to learn the SQL dialect, then list_tables and describe_tables to understand the schema before querying.
  - Use read_query to pull the complaints you need.
  - Group complaints by theme, category or severity, and highlight the top issues by frequency and severity.
  - Frame insights as product improvements, not support tickets.
  - Ground every claim in the data. If a query returns a large result, summarise the trends rather than listing records.
EOF
----

[cols="1,2", options="header"]
|===
| Field | Meaning

| `kind: native`
| An agent Orchestrate builds and runs, as opposed to an external one it federates to.

| `llm`
| The model, as `provider/model`. Orchestrate hosts this one, so it needs no API key of your own.

| `style: react_core`
| ReAct reasoning: plan, call a tool, read the result, decide what to do next.

| `tools`
| The four toolkit tools this agent may call. It cannot call anything outside this list.

| `starter_prompts`
| The suggested prompts in the chat UI. `is_default_prompts: false` replaces the generated ones.

| `welcome_content`
| The heading shown before the first message.

| `instructions`
| The system prompt. It names the tools and the order to use them in.
|===

== Step 2: Import and deploy

[source,sh,role="copypaste"]
----
orchestrate agents import -f complaints_analyser.yaml
----

[source,sh,role="copypaste"]
----
orchestrate agents deploy --name complaints_analyser
----

Importing registers the agent; deploying makes it available to chat with. After any change to the YAML, import again and redeploy.
