= Register the MCP Toolkit
:numbered:
:icons: font
:source-highlighter: highlight.js

The toolkit registers the remote MCP server and binds it to the connection.

== Step 1: Register the toolkit

[source,sh,role="copypaste",subs="attributes+"]
----
orchestrate toolkits add \
  --kind mcp \
  --name globex-complaints \
  --description "Details about complaints that were raised, and summaries from a product improvement perspective." \
  --url "https://globex-complaints.{openshift_subdomain}/read/mcp" \
  --transport "streamable_http" \
  --tools "*" \
  --app-id "globex-complaints-connection"
----

[cols="1,2", options="header"]
|===
| Flag | Meaning

| `--kind mcp`
| A remote MCP server, rather than a local Python or OpenAPI tool.

| `--url`
| The read-only endpoint on the complaints server, secured in Module 3.

| `--transport`
| Matches the transport the server was built with in Module 1.

| `--tools "*"`
| Imports every tool the server advertises. Naming tools here is one way to limit what reaches the workspace; the agent's own tool list is the other.

| `--app-id`
| The connection from the previous page. Orchestrate attaches a token from it to every call.
|===

== Step 2: Verify the discovered tools

The toolkit registers even if the server cannot be reached, so list the tools to confirm Orchestrate actually connected and read the definitions:

[source,sh,role="copypaste"]
----
orchestrate tools list
----

Four tools, namespaced by toolkit name are displayed in the terminal. The descriptions are the same as the `@Tool` annotations in the server code.
