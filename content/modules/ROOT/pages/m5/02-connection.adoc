= Create the Connection
:numbered:
:icons: font
:source-highlighter: highlight.js

A connection holds the endpoint and the OAuth credentials, separately from the tools that use them. Three commands: create it, configure the flow, set the credentials.

== Step 1: Create the connection

[source,sh,role="copypaste"]
----
orchestrate connections add -a globex-complaints-connection
----

`globex-complaints-connection` is the `app_id` the toolkit refers to on the next page.

== Step 2: Configure the OAuth2 flow

[source,sh,role="copypaste"]
----
orchestrate connections configure \
  -a globex-complaints-connection \
  --kind oauth_auth_client_credentials_flow \
  --type team \
  --env draft
----

[source,sh,role="copypaste"]
----
orchestrate connections configure \
  -a globex-complaints-connection \
  --kind oauth_auth_client_credentials_flow \
  --type team \
  --env live
----


....
[INFO] - Existing connection 'globex-complaints-connection' with environment 'draft' found. Updating configuration
[INFO] - Configuration successfully updated for 'draft' environment of connection 'globex-complaints-connection'.
....

[cols="1,2", options="header"]
|===
| Flag | Meaning

| `--kind`
| OAuth 2.0 client credentials, so Orchestrate authenticates as itself rather than as a user.

| `--type team`
| Credentials are shared by the team rather than stored per user.

| `--env draft`
| The development environment. A `live` environment can hold different credentials for the same `app_id`.
|===

== Step 3: Set up `connections` for both draft and live environments

[source,sh,role="copypaste",subs="attributes+"]
----
orchestrate connections set-credentials \
  -a globex-complaints-connection \
  --env draft \
  --client-id "{keycloak_realm_internal_globex_mcp_client_client_id}" \
  --client-secret "{keycloak_realm_internal_globex_mcp_client_secret}" \
  --token-url "https://sso.{openshift_subdomain}/realms/internal/protocol/openid-connect/token"
----

....
[INFO] - Setting credentials for environment 'draft' on connection 'globex-complaints-connection'
[INFO] - Credentials successfully set for 'draft' environment of connection 'globex-complaints-connection'
....


[source,sh,role="copypaste",subs="attributes+"]
----
orchestrate connections set-credentials \
  -a globex-complaints-connection \
  --env live \
  --client-id "{keycloak_realm_internal_globex_mcp_client_client_id}" \
  --client-secret "{keycloak_realm_internal_globex_mcp_client_secret}" \
  --token-url "https://sso.{openshift_subdomain}/realms/internal/protocol/openid-connect/token"
----


`globex-mcp-client` is a confidential client in the `internal` realm.

The credentials are passed as flags and stored by Orchestrate.
