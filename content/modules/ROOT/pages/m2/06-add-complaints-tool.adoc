= Give the Agent the Complaints Tool
:numbered:
:icons: font
:source-highlighter: highlight.js

The agent can read orders but has nothing to file a complaint with. A second MCP server, already running on the cluster, does exactly that. Connect it the same way you connected the orders server.

This one is greenfield: it was written as an MCP server and reaches the complaints table in the Globex database directly, with no REST API in between. The orders server from Module 1 is brownfield, wrapping an API that already existed. The agent cannot tell the difference -- it sees a list of tools either way.

== What the complaints server offers

The server is at `https://globex-complaints.{openshift_subdomain}/mcp` and exposes three tools:

[cols="1,2", options="header"]
|===
| Tool | What it does

| `create_complaint`
| Creates a complaint. Requires `orderId`, `productCode`, `issueType` and `description`; `severity` and `resolution` are optional.

| `get_complaint`
| Returns complaints for a product over a date range, sorted by severity.

| `update_complaint`
| Updates an existing complaint by ID.
|===

`create_complaint` needs an order ID and a product code. Both come out of `getOrdersByCustomerId` -- the product code is in the response because you kept it there when you shaped the payload in Module 1.

== Add a second MCP client

Same two files as before, both in the `globex-complaint-agent` folder. The transport type goes in `src/main/resources/application.properties`, next to the one for `orders`:

[source,properties,role="copypaste"]
----
quarkus.langchain4j.mcp.complaint.transport-type=streamable-http
----

The URL goes in `.env`, in the root of the same folder:

[source,properties,role="copypaste",subs="attributes+"]
----
quarkus.langchain4j.mcp.complaint.url=https://globex-complaints.{openshift_subdomain}/mcp
----

The client is named `complaint`. Nothing is shared with the `orders` client -- each has its own name, URL and connection.

== Give both toolboxes to the agent

In `ComplaintAgent.java`, replace the existing `@McpToolBox("orders")` annotation with one that lists both client names:

[source,java,role="copypaste"]
----
    @McpToolBox({"orders", "complaint"})
----

The agent now sees four tools: `getOrdersByCustomerId` from one server and the three complaints tools from the other. The model picks between them from their names and descriptions.

== Try it again

If the chatbot shows an error, restart dev mode in the `globex-complaint-agent` terminal:

[source,sh,role="copypaste"]
----
mvn quarkus:dev
----

Go back to the chatbot and type:

[source,text,role="copypaste"]
----
raise a complaint
----

The agent fetches the orders and asks which one. Answer with the product and the problem in one message:

[source,text,role="copypaste"]
----
I want to raise a complaints about the Stojo Collapsible Silicone Bottle. the cap was broken on arrival. It is such a critical problem for me. I want a replacement
----

Confirm when the agent asks. This time it calls `create_complaint` and comes back with a complaint ID:

image::m2/chatbot-complaint-raised.png[link=self,window=_blank]

The complaint is recorded against order 231 with the issue type, severity and resolution the agent worked out during the conversation.

[NOTE]
====
Nothing about the agent's code changed to make it use the new tool -- only one line of configuration and one annotation.
====
